# Maintained login with Steins identity

The earlier lab had no SDDM theme package: its configured `debian-theme` did not exist and SDDM fell back to its embedded white interface. This optional package depends on Debian's actual `sddm-theme-breeze` and supplies supported `theme.conf.user` presets: public original Akihabara artwork, current emblem, readable font size and clock. Breeze retains its authentication, users/sessions, keyboard, Caps Lock, error and accessibility controls. No private home/worldline state is read before authentication. This is configured upstream Breeze, not a bespoke authentication implementation.

Build with `python3 prototype/greeter/build.py`; install only through the guarded V3 deployment helper. Installation does not change the active greeter. Inside the isolated V3 guest, with the explicit `/run/steins-startup-v3-allow` marker, run `sudo /usr/lib/steins/login-lab.py apply`. It backs up both exact previous files, creates only its own SDDM cfg and Breeze's supported user override, and leaves the running session alone. Normal next logout/reboot uses them. Test actual fixture-password login; a theme-preview window is not authentication evidence.

Rollback inside the same guest: recreate the explicit V3 marker after reboot, then `sudo /usr/lib/steins/login-lab.py rollback`. Later edits cause refusal, backups are retained, and the original source/theme code is untouched. A cold lab reset is the broader recovery path. No host display manager is touched.

Project code/presets are MIT. Artwork is CC-BY-4.0, Steins;OS contributors. Upstream Breeze remains an unmodified Debian dependency with its own licenses. Its exact installed `Main.qml` reads `config.background`, `config.logo`, `config.showClock`, `config.fontSize`; it supports software rendering without blur. Keep this integration qualified against the shipped Plasma/SDDM versions. The lead engineer's V3 ledger distinguishes real rendering/login from configuration alone.
