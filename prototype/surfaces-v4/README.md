# V4 shared native surfaces

This candidate puts Terminal and Worldlines in the same neutral graphite, familiar-icon language as the V4 Plasma panel. The six atmospheres use the shared `/usr/share/steins-v4/tokens.json` contract for small digit/focus/selection strokes; selected cards and session rows stay neutral. Native Breeze window decorations, normal Qt controls, keyboard semantics and the existing worldline service remain in use.

No V3 source is edited. `steins-surfaces-v4` owns `/usr/bin/steins-navigator-v4`, `/usr/share/steins-v4/Navigator.qml`, the read-only token adapter and an explicit guest-only window preset. Its desktop ID is **steins-navigator-v4.desktop**. It depends on the separately packaged V4 identity and core service. The navigator uses the same `org.steinsos.Worldline1` session API and authoritative worldline state as V3; it creates no new settings format.

The terminal is a normal upgrade of **steins-terminal-v3**, version **0.3.0~v4.1**, keeping the existing executable and desktop ID. This avoids two packages owning the same files. Its source is copied under `terminal/`; engine content keeps the existing worldline ANSI palette while chrome reads V4 tokens. It opens the V4 navigator from its worldline button. Konsole remains available.

Build all artifacts and run the native tests with `python3 prototype/surfaces-v4/terminal/build.py`. The owned disposable Debian 13 Docker container supplies build and QML validation dependencies. Nothing is installed on the host. Outputs are under `dist/v4/surfaces/`. `python3 prototype/surfaces-v4/build.py` only packages the nonbinary surface assets and can also run independently.

The full six substantive terminal tests exercise real Bash PTYs, Unicode, resize/palette updates with stable PIDs, tab/rail linking, modal close races, ANSI fallback and removal of hidden controls from focus traversal. Four adapter tests verify current shared tokens, malformed input recovery and immutable fallback values. The QML probe loads the actual navigator, renders 880/650px layouts and activates switch/reapply/meter controls with keyboard Space through a deterministic backend fixture. Those captures prove layout in a software renderer; they do not prove a real session-bus request, Wayland focus or compositor/window decorations. The V4 VM ledger must record those separately.

`steins-v4-window-preset --status` is read-only. `--apply` and `--rollback BACKUP_DIRECTORY` are restricted to uid 1000 on hostname `steins-prototype` with QEMU/KVM detected. Applying writes only KDE `Icons.Theme=SteinsLab` and KWin `org.kde.kdecoration2.library=org.kde.breeze`, after backing up exact target files to the guest user's state directory. It does not alter button layout, shortcuts, panels or the worldline color scheme. No package post-install script applies the preset. Logout/login refreshes caches. Rollback explicitly restores the backed-up files, so apply/rollback around one controlled test before making other KDE configuration changes.
