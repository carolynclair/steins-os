# Steins;OS native Terminal — V4 surfaces candidate

This is the V4 chrome update of the V3 native Qt6 terminal, using unmodified QTermWidget 2.1 maintained by LXQt. Terminal emulation, PTYs, Unicode, bracketed paste, selection, scrollback and search remain upstream infrastructure. Native window-manager decorations stay in place. The package upgrades `steins-terminal-v3` to `0.3.0~v4.1`, preserving `/usr/bin/steins-terminal-v3` and its desktop ID. It does not change default-terminal settings or user shell files.

The copied source lives under `prototype/surfaces-v4/terminal/`; V3 sources remain intact. Chrome consumes `/usr/share/steins-v4/tokens.json` with safe matching defaults. Neutral graphite surfaces and quiet selected sessions remain stable across worlds. Narrow strokes and instrument digits use subdued atmosphere accents. PTY content receives the worldline terminal palette independently, preserving ANSI meaning and shell PIDs. The worldline button opens `steins-navigator-v4`.

Launch `steins-terminal-v3`, `steins-terminal-v3 --workdir "$HOME/Projects"` or `steins-terminal-v3 -- /bin/bash --noprofile --norc -i`. Arguments are passed directly; no command string is constructed. SHELL is honoured when executable, otherwise Bash is used. A login shell uses a real PTY. Normal shell exit closes its session.

Shortcuts remain Ctrl+Shift+T new, Ctrl+Shift+W close, Ctrl+Shift+C/V copy/paste, Ctrl+Shift+F search, Ctrl+PgUp/PgDown or Alt+1…9 session selection, Ctrl+Plus/Minus/0 text size, Ctrl+Shift+B session rail. Upstream multiline-paste confirmation and bracketed paste stay enabled. Konsole remains a fallback in the Session menu. Closing a running session or window requires a default-Cancel confirmation. Target identity is guarded across modal event loops; approval cannot close a different or newly created session. Hiding the rail removes its controls from keyboard focus traversal.

`python3 prototype/surfaces-v4/terminal/build.py` builds/tests/packages in an owned temporary container from `steins-os-builder:trixie`, then removes only that container. Build dependencies are installed only in the container. Output is under `dist/v4/surfaces/terminal/`. Runtime dependency versions are derived by dpkg-shlibdeps, with packaged V4 identity required. Rebuild requires Debian13 libqtermwidget-dev/libqtermwidget6-2 2.1.0-1, Qt6 development packages, CMake, GCC and libutf8proc-dev. QML probe dependencies are also container-only. The full source/build scripts accompany the package.

The six substantive QtTest cases compile the production class and launch actual Bash PTYs: TTY stdin/stdout, Unicode output, geometry changes and terminal background repaint with the same PID; linked tab/rail ordering, compact rail, default-Cancel close and normal exit; a target exiting during a tab-close confirmation; a new shell appearing during a whole-window confirmation; missing/invalid optional ANSI palettes; hidden rail focus exclusion. Init/cleanup add two QtTest pass lines. Tests also check that the displayed terminal background can change while neutral chrome retains its V4 surfaces and subdued token accent. Software/offscreen results do not qualify real Wayland focus, clipboard/IME, fractional scaling, SSH/editor compatibility or screen-reader behavior. The parent VM ledger records real-display evidence.

Known limits: no split panes, crash session recovery, remote profile manager, complete font-settings UI or full accessibility qualification. Conservative close checks ask even for an idle shell. Terminal programs may intentionally change their own colors; worldline changes do not reset their process state. Service loss leaves the PTY usable. Palette caches are application-private and content-addressed because QTermWidget caches schemes by path. Konsole/user profiles and divergence state files are never edited.
